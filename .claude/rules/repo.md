# This repo
tissue-lite: Python port of the Tissue vertex simulator (e74e457), restricted to the meristem mechanics models. The package `tissue_lite` lives in `source/tissue_lite/` (`arrays`, `topology`, `tissue`, `triangles`, `material`, `forces`, `stress`, `feedback`, `growth`, `diagnostics`, `model`, `solvers/`, `legacy/`, `output`, `cli`, `rand`). `reference/` builds Tissue and regenerates the regression data in `tests/data/`. Quirks are kept; suspected bugs go in `KNOWN_ISSUES.md`. Overview in `README.md`.

These rules override the shared ones where they differ.

- **Deps**: still on `uv` until migrated to pixi. `uv.lock` is committed and never hand-edited; use `uv add` (`--dev` for tools), `uv sync`, `uv run pytest [path]`, `uv run ruff check --fix`, `uv run ruff format`, `uv run ty check`. Ask before changing `uv.lock`.
- **Layout**: package code lives in `source/tissue_lite/`. Exception: the reference tooling stays in `reference/`. No top-level `code/` folder.
- **Regression data**: `tests/data/` is generated by `reference/generate.py` with `provenance.json`; never edit it by hand, and ask before regenerating it. Simulation outputs (`outputs/`, `vtk/`) and `reference/build/` are gitignored; never commit them.
- Read `README.md` before changing a module or script, and the docstring of the module you change.
- Settings → CLI arguments; no environment variables.

## Types and data
- Frozen dataclasses for records and parameters; mutable simulation state (`Tissue`, `ModelState`) is the exception.
- Arrays → NumPy, typed with the aliases in `tissue_lite.arrays` (`FloatArray`, `IntArray`, `BoolArray`). Per-cell state is a named `CellState` field; Tissue's slot numbers appear only in `tissue_lite.legacy.slots`, never as literal indices.
- Legacy file formats (`.init`, `.model`, solver files) are parsed in `tissue` and `legacy`; parsers raise `ValueError` on anything outside the supported subset.

## Numerics
Kernels that reproduce Tissue must keep its evaluation order: the same loop order, the same accumulation order and `libm` `pow`. A rewrite that changes any of these changes the last bit and breaks the bit-exact tests.
- Hot loops → Numba `@njit(cache=True)`, without `fastmath`.
- Sums → explicit `a*a + b*b + c*c`, or `np.bincount` weights, which add sequentially. Not `np.linalg.norm`, `einsum`, `np.add.reduceat` or `sum(axis=…)`, whose order differs.
- Powers in Hill terms → the Numba kernel (`feedback._hill_fraction`), since numpy's `power` differs from `libm` in the last bit.
- Run the slow fidelity tests (`uv run pytest -m slow`) after touching a kernel.
- Helpers called per cell or per triangle take scalars and tuples (`Vector`, `Matrix2`, `TriangleGeometry`). Numba counts references on every array argument per call: `compute_moduli(cells, c, …)` with the 28-array `CellState` cost 40 % of the force kernel. Small index lookups taking the mesh (`compute_triangle_geometry`, `get_rest_lengths`) are inlined by LLVM and measured free; anything larger, measure. The driver loops own the arrays and write the outputs.
- Outside the fidelity path (setup, IO, tests, analysis), prefer a numpy one-liner to a Python loop: `np.where`, broadcasting, fancy indexing, `np.bincount`, `np.linalg`. Mind memory on large meshes.

## Naming
- `update_` — advance or rewrite state in place (kernels writing into `CellState`, `Tissue` or a `TriangleMesh`), as Tissue's `update` does.
- The 3-vector and 2×2 helpers in `tissue_lite.triangles` (`dot`, `norm`, `cross`, `subtract`, `divide`, `combine`, `multiply`, `transpose`, `outer`) carry the operation's own name, as in formulas.
- Mesh indices carry their entity: `cell`, `wall`, `vertex`, `triangle` (`c`, `w`, `v`, `t` inside kernels). `tissue.BACKGROUND` (-1) marks the outside of a boundary wall and is not a cell. Kernels may keep Tissue's and Numerical Recipes' short names (`vd`, `cd`, `h`, `l0`) where they mirror the source.
- Array names say what each row holds (`cell_vars`, `wall_lengths`), not `arr` or `result_np`.

## Testing
- Build small synthetic meshes and arrays inline; fidelity tests read only `tests/data/` through the `tests/conftest.py` fixtures.
- Fidelity tests compare against Tissue output with exact equality where the case is bit-exact; never loosen a tolerance to make a test pass.
- Long fidelity runs carry `@pytest.mark.slow` and are excluded by default.
